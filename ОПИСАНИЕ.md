## Что это

**Blnk** — это открытый (open-source) финансовый **реестр (ledger)** с двойной записью (double-entry),
предназначенный для команд, строящих финтех-продукты: кошельки, банковскую инфраструктуру,
платёжные и кредитные системы, программы лояльности и любые приложения с большим объёмом транзакций.

Проект даёт разработчикам базовые «примитивы» для того, чтобы:
- записывать транзакции по принципам двойной бухгалтерской записи;
- управлять балансами и их историческими состояниями;
- сверять (reconcile) внутренние записи реестра с внешними выписками банков и провайдеров;
- управлять идентичностями (identity) и токенизировать персональные данные (PII).

Написан на **Go** (модуль `github.com/blnkfinance/blnk`, Go 1.25), предоставляет HTTP REST API.

## Ключевые возможности

### 1. Реестр (Ledger)
Двойная запись для управления балансами и транзакциями. Поддерживает:
- мониторы балансов (balance monitors) и снимки балансов (snapshots);
- исторические балансы (баланс «на момент времени» — `/balances/:id/at`);
- **inflight**-транзакции (двухфазные: hold → commit/void);
- запланированные (scheduled) и массовые (bulk) транзакции;
- овердрафты, возвраты (refunds), отклонения (rejections);
- коалесцирование (coalescing) и очереди транзакций.

### 2. Сверка (Reconciliation)
Сопоставление внешних записей (банковские выписки, экспорты платёжных процессоров)
с внутренними записями реестра по настраиваемым правилам и стратегиям сопоставления.

### 3. Управление идентичностями (Identity)
Создание и управление идентичностями, токенизация PII, связывание идентичностей
с балансами и транзакциями.

### 4. Lineage / Hash-chain
Отслеживание происхождения движений средств (lineage: credit/debit/allocation, outbox, shadow)
и обработка hash-chain для целостности данных (см. `chain_worker.go`, `cmd/verify_chain.go`).

## Архитектура и структура кода

| Каталог / файл | Назначение |
|---|---|
| `*.go` (корень) | Бизнес-логика домена: `ledger.go`, `balance.go`, `transaction*.go`, `reconciliation*.go`, `identity.go`, `lineage*.go`, `webhooks.go`, `queue*.go` |
| `cmd/` | Точка входа и команды CLI: `main.go`, `server.go` (HTTP-сервер), `workers.go`, `migrate.go`, `verify_chain.go` |
| `api/` | HTTP-слой (REST-эндпоинты на базе Gin): ledgers, balances, transactions, identities, reconciliation, api-keys, hooks, admin |
| `model/` | Доменные модели и типы данных |
| `database/` | Слой доступа к данным (репозитории) поверх PostgreSQL |
| `config/` | Конфигурация приложения |
| `internal/` | Внутренние пакеты: `cache`, `lock`, `metrics`, `traces`, `search`, `tokenization`, `notification`, `redis-db`, `pg-conn`, `pg-backups`, `hooks`, `hotpairs` и др. |
| `sql/` | SQL-миграции схемы БД |
| `infrastructure/`, `docker-compose*.yaml`, `Dockerfile` | Развёртывание и инфраструктура |
| `tests/` | Интеграционные тесты |

### Технологический стек (основные зависимости)
- **Web:** `gin-gonic/gin` — HTTP-фреймворк
- **БД:** PostgreSQL (драйверы pgx / lib/pq), SQL-миграции
- **Очереди/задачи:** `hibiken/asynq` (+ `asynqmon` для мониторинга) поверх Redis
- **Кэш/блокировки:** Redis (`redis/go-redis/v9`, `go-redis/cache`)
- **Поиск:** Typesense (`typesense-go`)
- **Наблюдаемость:** Prometheus (метрики), OpenTelemetry + Jaeger (трейсинг)
- **TLS:** `caddyserver/certmagic`

### Сервисы при запуске (`docker-compose.yaml`)
`server`, `worker`, `redis`, `postgres`, `typesense`, `jaeger`, `prometheus`.

## REST API (примеры эндпоинтов)
- **Ledgers:** `POST/GET /ledgers`, `GET /ledgers/:id`, `POST /ledgers/filter`
- **Balances:** `POST/GET /balances`, `GET /balances/:id`, `GET /balances/:id/at` (на момент времени),
  `GET /balances/:id/lineage`, `POST /balances-snapshots`, `POST /balance-monitors`
- **Transactions:** `POST /transactions`, `POST /transactions/bulk`,
  `PUT /transactions/inflight/:txID` (commit/void), `POST /refund-transaction/:id`
- **Identity, API-keys, Reconciliation, Hooks, Admin** — соответствующие группы маршрутов в `api/`.

## Примеры применения
Кошельки, депозиты/выводы, обмен/ордера (crypto), кредитование, программы лояльности,
AI-биллинг, эскроу-платежи.

